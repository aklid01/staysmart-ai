# Architectural decisions

Decisions are recorded with their rationale. Where a decision refers to a component that is not built yet, it is marked as a decision only, not an implemented capability.

| # | Decision | Rationale | Status |
| --- | --- | --- | --- |
| 1 | uv with `pyproject.toml`, `uv.lock` and a pinned `.python-version` | This machine has several Python 3.13 interpreters and `pip` targets a different one than `python`. A project virtual environment via `uv sync` and `uv run` removes ambiguity and makes setup reproducible. | Implemented |
| 2 | Official MCP Python SDK pinned to 2.x (`mcp>=2.3,<3`) | 2.x is the current stable line. It replaces v1 `FastMCP` with `MCPServer` and adds a first-class `Client`. Most tutorials show v1, so the version is pinned explicitly and verified with a smoke import before any MCP code exists. | Decided, verified by Phase 0 import check |
| 3 | Starlette, not FastAPI | Required by the project brief. The MCP SDK also depends on Starlette, so no extra web framework is needed. | Decided |
| 4 | In-process `HotelProvider` Protocol instead of a separate mock REST service | The brief asks for a replaceable local provider and forbids microservices without demonstrated need. A second HTTP process would add failure modes and setup cost without educational value. A real REST provider can later implement the same Protocol. | Decided, Phase 1 |
| 5 | Versioned JSON dataset with deterministic date-aware inventory | Supports realistic check-in and check-out validation, multi-night totals, sold-out nights and partial availability, while keeping tests deterministic without a database. | Decided, Phase 1 |
| 6 | `hashlib.sha256` seeding and a fixed anchor date | Avoids Python's randomized `hash()` and any `datetime.now()` dependence, so the same query always produces the same result and the E2E artifact is reproducible. | Decided, Phase 1 |
| 7 | Provider exposes three operations only | `compare_hotels` and `get_hotel_policies` are derivations over raw facts. Keeping them in a service layer preserves provider replaceability and keeps MCP tool schemas independent of the data source. | Decided, Phase 2 |
| 8 | Configurable currency with a USD default dataset | International sample destinations; currency remains explicit on every monetary field and configurable through `STAYSMART_CURRENCY`. | Decided, Phase 1 |
| 9 | Spec-first tests and a reproducible E2E artifact | Project rules require tests before implementation and E2E tests with a checkable artifact. The golden file is authored from the behavioral contract, not generated by the implementation, to avoid tautological change detection. | Decided, Phase 1 |
| 10 | No formatter or linter configured | Project rules require asking permission before configuring formatting tools. Revisit in Phase 7. | Implemented |
| 11 | `fastembed` and `openai` are not declared yet | FastEmbed depends on onnxruntime and tokenizers, which can lag new Python versions. Deferring these dependencies keeps the Phase 0 lock resolvable; uv can provision Python 3.12 later if needed. | Decided |
| 12 | Exactly the seven documentation files named in the brief | Keeps the documentation surface small and avoids describing features that do not exist. Unimplemented documents carry explicit status stubs. | Implemented |

## Explicitly out of scope

- Real hotel reservations, payments or booking transactions.
- Any live Google Hotels integration, scraping or reverse-engineered endpoints.
- Docker, microservices, hosted databases or message queues.
- Claiming that mock prices, ratings or availability are verified live data.
